# CONTRIBUTING

First of all, thank you for considering contributing to Ford Triplog.

Whether you report a bug, suggest a new feature, improve the documentation or submit code, every contribution helps improve the project.

---

# Ways to Contribute

There are many ways to contribute.

Examples include:

- Reporting bugs
- Suggesting new features
- Improving documentation
- Improving translations
- Testing new releases
- Reviewing pull requests
- Submitting code improvements

---

# Before Opening an Issue

Please verify the following before creating a new issue:

- Home Assistant is updated.
- Ford Triplog is updated to the latest version.
- The FordPass integration is working correctly.
- The documentation has been reviewed.
- Existing GitHub issues have been searched.

Many common questions are already answered in the documentation.

---

# Bug Reports

A good bug report should include:

- Ford Triplog version
- Home Assistant version
- FordPass integration version
- Operating system
- Clear description of the problem
- Steps to reproduce
- Expected behavior
- Actual behavior

Whenever possible, include the Home Assistant diagnostics file.

---

# Feature Requests

Feature requests are always welcome.

A useful feature request should explain:

- the problem being solved
- the proposed solution
- possible alternatives
- expected benefits

Please provide real-world use cases whenever possible.

---

# Pull Requests

Before submitting a pull request:

- Update to the latest development branch.
- Ensure the project builds successfully.
- Test your changes.
- Update documentation if necessary.
- Keep changes focused on a single topic.

Large pull requests are more difficult to review than smaller, focused improvements.

---

# Coding Style

Please follow the standard Home Assistant development guidelines.

General principles include:

- Clear and readable code
- Meaningful variable names
- Type hints where appropriate
- Consistent formatting
- Small, reusable functions

Avoid unnecessary complexity.

---

# Documentation

Documentation improvements are always appreciated.

Please ensure that documentation is:

- Written in English
- Clear and concise
- Grammatically correct
- Consistent with the existing documentation

---

# Translations

Translation improvements are welcome.

Please:

- Use natural wording.
- Follow existing terminology.
- Keep translations consistent across the project.

---

# Testing

Every contribution should be tested before submission.

Recommended testing includes:

- Fresh installation
- Upgrade from a previous version
- Trip recording
- Charging session detection
- Charging location recognition
- Home Assistant restart
- Configuration flow
- Options flow

---

# Backward Compatibility

Whenever possible, new features should not break existing installations.

Please avoid:

- Renaming stable entities
- Breaking storage compatibility
- Removing existing functionality without migration

---

# Commit Messages

Use short, descriptive commit messages.

Examples:

```
Add charging location resolver
```

```
Improve Smart Trip detection
```

```
Fix charging session recovery
```

```
Update documentation
```

---

# Branches

Recommended workflow:

```
main
```

Stable releases.

```
develop
```

Active development.

Feature branches:

```
feature/new-feature
```

Bug fixes:

```
bugfix/fix-description
```

---

# Pull Request Checklist

Before submitting a pull request, verify the following:

- [ ] Code compiles successfully.
- [ ] New functionality has been tested.
- [ ] Existing functionality still works.
- [ ] Documentation has been updated.
- [ ] No unnecessary files are included.
- [ ] Commit history is clean.

---

# Development Goals

Ford Triplog follows several core principles:

- Privacy by design
- Local-first architecture
- Native Home Assistant integration
- Human-readable storage
- Stable entity names
- Reliable operation
- Comprehensive documentation

Contributions should support these goals whenever possible.

---

# Code of Conduct

Please be respectful when interacting with other contributors.

Constructive feedback is encouraged.

Harassment, personal attacks or inappropriate behavior are not acceptable.

The goal is to build a welcoming and collaborative open-source project.

---

# Questions

If you have questions before contributing, feel free to open a GitHub Discussion or Issue.

Constructive discussions often lead to better solutions.

---

# Thank You

Thank you for helping improve Ford Triplog.

Your time, ideas, testing and contributions are greatly appreciated.
